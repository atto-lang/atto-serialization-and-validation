# Zorde verified contracts → generated guest execution

**Status:** Experimental, unqualified. This is an execution plan and test
harness, not evidence that the private source has passed CI.

The integrated branch from draft PR #28 contains exactly the canonical
`src/zorde/compiled_registry.ores` and build bridge from draft PR #20,
plus independent TypeSpec, JSON Schema, WIT, Dafny and corpus blobs from
draft PR #16. These files stay inside the existing private source repository.

The integrated CI workflow first runs the actual Node regression suite,
pins the official TJSV action, compares independently authored peer
contracts, rebuilds Contract IR against the exact source and generated
witness, then emits:

- `artifacts/zorde-generated/registry-plan.json`: derived scalar metadata.
- `artifacts/zorde-generated/registry-specs.ores`: generated Oreslang
  declarations for the canonical `ZordeScalarRegistry`.
- `artifacts/zorde-generated/registry-smoke.ores`: *pilot-specific*
  executable guest that imports those generated declarations and checks
  integer bounds, string length boundaries and malformed UTF-8 rejection.
- `artifacts/zorde-generated/build-complete.json`: SHA-256 fingerprints
  of all three artifacts and explicit `guestSmokeCompiled:false`,
  `guestSmokeExecuted:false`, `nativeGuestExecuted:false` and
  `releaseReady:false` fields.

The pilot guest intentionally refuses generation unless the declaration
inventory consists of the reviewed `Zorde.Validation.Port` (1–65535)
and `Zorde.Validation.ShortLabel` (length 1–64). Changes to schemas
require the test witnesses and contract/version review to change together.
**No compiler verification is inferred from emitting guest source.**

## Scalar format parity finding (October 19, 2026)

An independently authored **public synthetic scalar canary** in
[ORESoftware TypeSpec validator PR #238](https://github.com/ORESoftware/typespec-json-schema-validator/pull/238)
showed that the official TypeSpec JSON Schema emitter does **not**
write `format: "int32"` on a bounded `int32` scalar. Adding that
annotation to the peer-authored schema produces a genuine TJSV
`generated-authored-semantic-mismatch` at `#/format` even when the
instance differential validators happen to agree. The pilot `Port`
peer authority therefore retains `type: "integer"`, `minimum: 1` and
`maximum: 65535` **without** an independently invented `format`.
Those explicit bounds remain within the signed int32 domain.

This is not permission to discard all `format` constraints generally:
the two authorities must strictly agree on any present annotation.
The source-org's pinned TJSV compiler still needs its own exact-head
verification before treating this private contract as admitted.

## FIFO-before-timeout native output fix (October 20, 2026)

An adversarial FIFO in the native log destination reveals a subtle
`set -C` (Bash noclobber) limitation: `> log` opens an existing FIFO
**before** `timeout` starts the intended guest command. On Linux, that
redirection can block indefinitely instead of failing as a safe,
already-existing output path. Ordinary file/symlink/hardlink protection
does not prevent the FIFO hang.

The native guest runner now uses a short isolated `python3 -I -S` helper
which opens the approved evidence directory by following **directory FDs**
from the filesystem root with `O_DIRECTORY|O_NOFOLLOW`, checks that the
final directory is private and owned by the caller, then opens the log
with `O_CREAT|O_EXCL|O_NOFOLLOW`. The already-open descriptor is passed
as the timed guest process's stdout/stderr. A child `RLIMIT_FSIZE` of
**16 MiB** bounds native guest output; nonzero guest exit or output
overflow refuses qualification. A path-based Bash redirection is no
longer involved in starting the guest.

The committed private regression
`tests/source_free/test_zorde_native_log_admission.py` runs the
**exact inline Python admission helper** against ten synthetic scenarios:
fresh output; existing regular file, FIFO, symlink, dangling symlink and
hardlink; symlinked and overly-permissive evidence directories; compiler
nonzero exit; and over-limit output. Its source-org CI stage is mandatory,
but **not executed** while the original organization cannot allocate a
runner. The native guest launcher must also receive an independently
approved `NODE_BIN` and `EXPECTED_NODE_SHA256` for the corpus identity
check, in addition to the compiler and source/evidence approval inputs.

An independently authored, **source-free** version on public
[TJSV draft PR #241](https://github.com/ORESoftware/typespec-json-schema-validator/pull/241)
completed **22/22 hosted Linux checks** in
[Actions run #39443649912](https://github.com/ORESoftware/typespec-json-schema-validator/actions/runs/39443649912)
at public commit `4cca47bbd4916ba23a35f4b4f0023f35f7cbbe36`.
It demonstrably blocks the old Bash FIFO operation before the command
timeout and then proves exclusive descriptor-opening refuses immediately.
These are independently authored OS security tests **only**, not private
Zorde source or native guest tests. No private Git tree or files were
mirrored or published.

## October 19 source-local Node ancestor and private-log hardening

The source-local Node qualification harness previously checked that
`NODE_BIN` and `ZORDE_EVIDENCE_DIR` were not direct symlinks, but it could
still traverse a *symlinked ancestor directory*. A synthetic Git repository
reproduced both bypasses using real Node 22: a symlinked Node binary parent
and a symlinked evidence parent each exited 0 and issued a receipt.

The harness now requires an absolute evidence directory and uses `os.lstat`

test-log redirection additionally uses Bash noclobber. Before receipt issuance,
the log is opened with `O_NOFOLLOW | O_NONBLOCK` and must be a unique,
owner-controlled private regular file of at most 16 MiB; the receipt hashes
the bytes read from that verified descriptor. These guards reduce filesystem
substitution risks but cannot certify a compromised same-UID executor.

## Fresh ignored-output hardening (October 19, 2026)

The **source-local** Contract IR gate now requires `artifacts` to be wholly
absent before starting the private Node and TypeSpec steps. In particular,
`test -e` alone does not detect a dangling symlink, and the previous

## BASH_ENV fixture self-test and launcher source-path hardening (October 19, 2026)

## Mandatory isolated launcher for source-local Contract IR qualification

Run the private Contract IR gate using
`python3 -I -S scripts/launch-zorde-contract-source-local.py`, **not**
`bash scripts/test-zorde-contract-source-local.sh`. Noninteractive Bash
processes execute the file named by an inherited `BASH_ENV` variable
**before the shell script's first statement**, so the shell cannot defend

## Python optimization flag hardening — October 19, 2026

The source-local Node, Contract IR and generated-guest qualification scripts use
Python assertions as fail-closed evidence admission predicates. An adversarial
standalone check established that an ordinary `python3` invocation with
`PYTHONOPTIMIZE=1` silently removes `assert False`, allowing a signer to
proceed past disabled checks. Running `python3 -I -S` with that same hostile
environment preserves the assertion and refuses the forged evidence.

All Python heredoc invocations in the three source-local qualification scripts
now use **`python3 -I -S -`**, isolating the interpreter from environment
injection and site startup customization. The integrated workflow's Python
security tests and the Node-guard-to-Python regression invocation likewise
use isolated no-site Python. The synthetic signer regression explicitly checks
that Python assertions are enabled and includes a twelfth case: a forged child
test count with `PYTHONOPTIMIZE=1` injected must not issue a static receipt.
The bootstrap regression checks that no Python evidence heredoc regresses to
an unisolated invocation.
