# Zorde verified contracts → generated guest execution

**Status:** Experimental, unqualified. This is an execution plan and test
harness, not evidence that the private source has passed CI.

The integrated branch from draft PR #28 contains exactly the canonical
`src/zorde/compiled_registry.ores` and build bridge from draft PR #20,
plus independent TypeSpec, JSON Schema, WIT, Dafny and corpus blobs from
draft PR #16. These files stay inside the existing private source repository.

The integrated CI workflow first runs the actual Node regression suite,
pins the official TJSV action, compares independently authored peer
contracts, rebuilds Contract IR against the exact source and generated
witness, then emits:

- `artifacts/zorde-generated/registry-plan.json`: derived scalar metadata.
- `artifacts/zorde-generated/registry-specs.ores`: generated Oreslang
  declarations for the canonical `ZordeScalarRegistry`.
- `artifacts/zorde-generated/registry-smoke.ores`: *pilot-specific*
  executable guest that imports those generated declarations and checks
  integer bounds, string length boundaries and malformed UTF-8 rejection.
- `artifacts/zorde-generated/build-complete.json`: SHA-256 fingerprints
  of all three artifacts and explicit `guestSmokeCompiled:false`,
  `guestSmokeExecuted:false`, `nativeGuestExecuted:false` and
  `releaseReady:false` fields.

The pilot guest intentionally refuses generation unless the declaration
inventory consists of the reviewed `Zorde.Validation.Port` (1–65535)
and `Zorde.Validation.ShortLabel` (length 1–64). Changes to schemas
require the test witnesses and contract/version review to change together.
**No compiler verification is inferred from emitting guest source.**

## Scalar format parity finding (October 19, 2026)

An independently authored **public synthetic scalar canary** in
[ORESoftware TypeSpec validator PR #238](https://github.com/ORESoftware/typespec-json-schema-validator/pull/238)
showed that the official TypeSpec JSON Schema emitter does **not**
write `format: "int32"` on a bounded `int32` scalar. Adding that
annotation to the peer-authored schema produces a genuine TJSV
`generated-authored-semantic-mismatch` at `#/format` even when the
instance differential validators happen to agree. The pilot `Port`
peer authority therefore retains `type: "integer"`, `minimum: 1` and
`maximum: 65535` **without** an independently invented `format`.
Those explicit bounds remain within the signed int32 domain.

This is not permission to discard all `format` constraints generally:
the two authorities must strictly agree on any present annotation.
The source-org's pinned TJSV compiler still needs its own exact-head
verification before treating this private contract as admitted.

## Execute on an independently approved source-local runner

The source repository's hosted Actions are currently failing with no
test steps executed. The supported alternative is an approved ephemeral
runner **inside the source confidentiality trust boundary**—not a
cross-organization Git mirror.

Obtain the exact source head SHA and root Git tree SHA from the reviewed
integration PR. Independently review and pin the compiler executable and
its transitive runtime provenance. Run the integrated static workflow or
equivalent TJSV producer plus `verify-ir` workflow within that same
source trust boundary. Record the independent SHA-256 hashes of the
produced Contract IR, parity report and consumer verification receipt.

Then invoke:

```bash
export EXPECTED_SOURCE_SHA='<approved 40-hex commit SHA>'
export EXPECTED_SOURCE_TREE='<approved 40-hex root tree SHA>'
export ORESLANG_BIN='/approved/absolute/compiler-executable'
export EXPECTED_COMPILER_SHA256='<independently approved 64-hex binary digest>'
export EXPECTED_CONTRACT_IR_SHA256='<reviewed IR file digest>'
export EXPECTED_PARITY_REPORT_SHA256='<reviewed parity receipt digest>'
export EXPECTED_VERIFICATION_SHA256='<reviewed consumer verify-ir receipt digest>'
export ZORDE_EVIDENCE_DIR='/approved/private/fresh/0700/directory'

bash scripts/test-zorde-generated-guest-source-local.sh
```

The script refuses a different source SHA/tree, dirty tracked files,
unexpected untracked files, a compiler symlink/digest mismatch, a
group/world-accessible evidence directory, missing source-bound
`verify-ir` evidence, changed generated bytes and native guest failure.
On success it issues a new, exclusive, digest-bound native log receipt with
`native_guest_executed:true`, but **still** records
`cross_backend_parity_certified:false` and `release_ready:false`.

**Important:** Manually computing all six expected hashes from attacker
controlled bytes is not independent approval. The approved operator must
review the verifier producer/toolchain and the exact submitted evidence.
The source-local binary SHA alone does not attest the entire compiler
dependency closure, and two successful guests on different backends do
not automatically prove actor shareability or WIT ABI correctness.

## Remaining independent gates

The existing `scripts/test-zorde-registry-source-local.sh` covers the
full native suite and negative Oreslang visibility controls on a clean
checkout. It is separate from the generated guest tests; don't substitute
one result for the other. Repeat all advertised contract/guest tests
against Java/Graal and LLVM and compare diagnostic codes/metrics. Qualify
WIT against real Component Model parser/bindings, Dafny under pinned
verification tools, and concurrency/actor ownership independently.

The active source-export incidents in
`oreslang-platform-conformance` #22 and #77 explicitly prohibit using a
different organization merely because it has available GitHub Actions
minutes. Privacy, exact Git-tree identity and green CI are three
**separate** required properties.

## Reviewed instance-corpus continuity

Before source generation, `scripts/zorde-static-contract-ir.mjs` independently
reconstructs the pinned TJSV corpus SHA-256 from checked-in
`contracts/zorde/scalar-instances/{Port,ShortLabel}/{valid,invalid}/*.json`.
The workflow requires `--instances=contracts/zorde/scalar-instances`,
exactly matched source-bound positive and negative examples for every
admitted declaration, and no unknown or unasserted corpus entries.

The native harness rechecks the current corpus identity using the same
read-only bridge before guest execution. Its immutable pre-execution
manifest contains **18 exact file entries** (nine source/derived inputs and
nine independent corpus fixtures), verifies every byte afterward, and
checks the same manifest again at receipt issuance. A modified or renamed
fixture cannot be silently substituted under a stale parity receipt.
Actual Node filesystem and native execution remain unverified until an
authorized runner executes the tests.

The pinned TJSV v1 receipt stores the corpus digest at
`configuration.differential.instanceCorpusDigest`; it **does not**
duplicate that field inside `report.differential`. This distinction
was confirmed by funded public synthetic TJSV compiler-backed CI.

## Native guest import-closure sealing (October 19, 2026)

The source-local harness now discovers and seals the **recursive static Oreslang
import closure** of the generated registry smoke and registry specifications,
not only the generated files and independently reviewed JSON fixtures. The
current pilot adds ten implementation/test support modules to the existing
18 source-authority, receipt, guest and fixture inputs (28 total).

Unknown import grammar, missing modules, traversal outside the private source
checkout, symbolic links, excess recursion and duplicate/altered source bytes
must stop execution or the final receipt. The manifest records
`staticGuestImportClosure`; its hash-bound contents are checked after the
guest and before the receipt is issued. The source-free host test checks the
exact expected import graph. This **does not attest the compiler binary's
transitive dependency closure** and cannot replace real native guest tests.

## Source-local Node security qualification (without GitHub Actions minutes)

The actual Node SHA-256, strict JSON, reviewed-corpus mutation, source-bound
build CLI and source-local runner preflight tests can run **before** the
TypeSpec and native backend stages on an approved source-local Linux machine.
This neither exports the private Git tree nor requires GitHub Actions minutes.

Review the exact source commit and Git tree, Node 22 executable SHA-256,
and destination path **independently**, not from attacker-supplied candidate
bytes. Create a fresh 0700 private evidence directory outside checkout.

```bash
export EXPECTED_SOURCE_SHA='<reviewed 40-hex private source commit>'
export EXPECTED_SOURCE_TREE='<reviewed 40-hex Git root tree>'
export NODE_BIN='/approved/absolute/node22-executable'
export EXPECTED_NODE_SHA256='<independently reviewed 64-hex binary digest>'
export ZORDE_EVIDENCE_DIR='/approved/private/fresh-0700-directory'

bash scripts/test-zorde-node-source-local.sh
```

The script denies symlinked Node executables, incorrect SHA/tree, dirty
tracked checkout, unexpected untracked source files, unsafe evidence folders,
changed Node binaries, nonzero test exits, missing TAP counts, failures and
skips. It demands at least 80 executed Node cases and rechecks the source and
Node executable after the tests. A successful invocation issues the exclusive
`zorde-node-real-suite-receipt.json` with exact source/tree/binary/log digests.

The receipt can certify `real_node_crypto_filesystem_tests_executed:true`,
but explicitly keeps `generated_oreslang_guest_executed:false`,
`cross_backend_parity_certified:false`, and `release_ready:false`.

The shell gate was smoke-tested in a **synthetic** local Git checkout with
90 passing dummy Node tests, and an incorrect source SHA was refused. That
is not private Oreslang source-test evidence. The actual tests on the exact
private revision are still required before this gate can be marked qualified.


## Node TAP false-success hardening (October 19, 2026)

An adversarial synthetic Node run containing **89 passing tests and one TODO**
previously exited with status 0, met the old `tests>=80` and `fail=0`
checks, and caused the unqualified shell harness to issue a false-success
receipt for 90 passes. The previous receipt parser was insufficient.

The source-local Node harness now requires exactly one `# tests`, `# pass`,
`# fail`, `# skipped`, `# todo`, and `# cancelled` TAP summary. It
requires at least 80 tests, *every one passing*, and zero failures/skips/TODO/
cancellations. The same conditions are checked again from the bytes used to
create the final receipt; `source_free_test_cases_passed` is the true
`# pass` count, not merely the registered test count.

**Reproduced with real local Node 22 and Bash:** 90/90 synthetic passing
tests produce a non-release receipt; 89 passing + one TODO and 89 passing +
one skipped test both fail closed and create no receipt. Source SHA/tree
mismatches, binary SHA mismatch and evidence-folder symlink also fail closed.
A permanent synthetic-checkout regression exercises this shell gate through
`test_zorde_native_guard.mjs`.

The repaired script's exact reviewed Git blob SHA is
`f753971a86cf3cb55db56986cec51f2a46bbb4d3`. A botched intermediate
text-replacement commit was superseded before qualification; do not use
any preceding script blob or synthetic receipt to assert private Zorde tests.

This verifies the *test harness control logic* only. Real private Zorde
Node/filesystem/cryptographic code has still not been exercised on its source
tree, nor have the Graal/LLVM/WIT/Dafny gates passed.
