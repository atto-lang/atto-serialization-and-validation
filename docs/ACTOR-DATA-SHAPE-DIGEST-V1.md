# Candidate canonical descriptor digest v1

Canonical input is a finite reachable graph of explicitly named descriptor nodes for the restricted CBOR positional, Protobuf wire-kind or FlatBuffers scalar root-table profile. Node IDs/field names are restricted ASCII [A-Za-z0-9_.:-], 1..128 bytes. Version is 1..4294967295 (positive u32, matching IPC codec-profile commitment); node count <=256, fields per node <=1024 and total <=4096. Reject duplicate IDs, field names/slots, dangling or unreachable nodes, illegal Protobuf tags, noncontiguous CBOR positions, and nonscalar packed elements. Named recursive references are encoded as IDs, never recursively expanded. The canonical bytes are newline-delimited ASCII, final LF, starting ATTO-SHAPE-1, codec, decimal version, root ID, node count, then each node in ASCII ID order: ID, kind, field count, then each field in numeric slot order: decimal slot, name, target ID. Hash SHA-256 over these bytes. Slot ordering is semantic, declaration iteration ordering is not. The codec profile is deliberately restricted and does not represent all Atto ADT semantics, signed/zigzag/defaults/cardinality, optional fields or general FlatBuffers. The restricted FlatBuffers profile admits exactly one reachable root table with 1–64 contiguous zero-based slots targeting bool, i64, u32 or f64 scalar leaves; nested tables, recursion, vectors and strings are refused. The codec token already participates in the canonical commitment, so adding this distinct restricted profile preserves all existing CBOR/Protobuf canonical bytes. The Rust canonicalizer is checked against the existing shared vectors and fixed SHA-256 golden digests. The independent JavaScript implementation is retained as a reference. The host digest helper uses the trusted Linux /usr/bin/sha256sum executable, not a new cryptographic implementation or guest runtime. No compiler descriptor generation or backend parity claim. The registered host must bind the actual decoder descriptor to the digest; do not trust a peer-supplied digest.

The six FlatBuffers vectors are carried unchanged from #76. All 21 previous vectors retain their original expected behavior. The two reordered scalar descriptors share SHA-256 `a554bfe97f5de4da0356747008dc94cf6eb808095c8566a9f8a5ebe9db1f9344`, independently checked using the canonical ASCII byte stream. The Rust profile does not itself verify FlatBuffers wire admission or establish compiler-generated schema authority.
