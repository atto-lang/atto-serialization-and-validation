# Candidate canonical descriptor digest v1

Canonical input is a finite reachable graph of explicitly named descriptor nodes for the restricted CBOR positional or Protobuf wire-kind profile. Node IDs/field names are restricted ASCII [A-Za-z0-9_.:-], 1..128 bytes. Version is 1..2147483647 (matches Java signed positive binding); node count <=256, fields per node <=1024 and total <=4096. Reject duplicate IDs, field names/slots, dangling or unreachable nodes, illegal Protobuf tags, noncontiguous CBOR positions, and nonscalar packed elements. Named recursive references are encoded as IDs, never recursively expanded. The canonical bytes are newline-delimited ASCII, final LF, starting ATTO-SHAPE-1, codec, decimal version, root ID, node count, then each node in ASCII ID order: ID, kind, field count, then each field in numeric slot order: decimal slot, name, target ID. Hash SHA-256 over these bytes. Slot ordering is semantic, declaration iteration ordering is not. The codec profile is deliberately restricted and does not represent all Atto ADT semantics, signed/zigzag/defaults/cardinality, optional fields or FlatBuffers. Changing the supported grammar requires a new profile. Independent JS and Python implementations compare exact bytes/digests on shared fixtures. No compiler descriptor generation or backend parity claim. The registered host must bind the actual decoder descriptor to the digest; do not trust a peer-supplied digest.
