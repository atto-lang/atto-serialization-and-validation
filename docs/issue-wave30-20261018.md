# Zorde dual-authority release admission — draft 2026-10-18

Issue #18: independently authored TypeSpec and JSON Schema Draft 2020-12 are peer authorities. A generated TypeSpec JSON-Schema witness is compared **in memory** with the manually authored schema using pinned `tjsv`. WIT expresses an independent interface boundary, not a JSON-Schema translation.

## Executable gate order
1. Install from reviewed, hash-locked dependency graph; verify TypeSpec compiler, emitter, `tjsv`, WIT parser, and formal verifier versions. No unlocked installation in release CI.
2. Parse both authorities; produce the generated witness; reject schema drift and mismatched valid **or** invalid instance verdicts.
3. Mutate required fields, bounds, extraProperties, unions, nullable/Option variants, unknown enum members; each mutant must return a nonzero drift status (the planned `tjsv` CLI contract is exit 2).
4. Run a real parser over WIT package/world; projection mismatches or unsupported ABI features fail closed.
5. Run `dafny verify` over the exact revision of parity invariants; bind verdict to input SHA-256, toolchain digest and commit/tree SHA.
6. Independently run host/guest Zorde against Java/Graal, LLVM and hosted Wasm; schema-only success is not native runtime conformance.

## Attack vectors
- A TypeSpec emitter changes defaults while the hand-written schema remains unchanged.
- Duplicate keys or case-normalized identifiers change interpreted schema authority.
- A WIT signature uses an illegal primitive or silently changes an import capability.
- CI reports green from a 0-step runner failure, a wrong Git tree, or a public cross-org private-source mirror.

**Status:** acceptance gates only, not implementation or verified proof. Runner and allowed private source retention must be revalidated before release.
